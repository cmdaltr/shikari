How Archer Works

Architecture, Libraries, and AI-Powered Detection Generation

📋 Overview

Archer is an automated threat detection generator that transforms MITRE ATT&CK threat intelligence into production-ready detection queries for Splunk and Microsoft Defender for Endpoint (MDE). It combines machine learning from community query repositories with optional AI enhancement to create comprehensive, correlated detection coverage in minutes.

🎯 What It Does

  • Generates vendor-specific detection queries
  • Creates multi-stage attack correlations
  • Produces attack flow visualizations
  • Extracts IOCs from threat reports

⚡ Why It's Fast

  • Template caching (90% faster)
  • Parallel processing (4x speedup)
  • Async I/O operations
  • Pre-compiled patterns

🔧 How It Works

  • Learns from 10,000+ community queries
  • Applies MITRE ATT&CK mappings
  • Generates vendor-optimized syntax
  • Validates and enriches outputs

🏗️ Architecture

CLI/Command-Line Architecture

The CLI version provides direct programmatic access to Archer's detection generation engine. It's designed for automation, CI/CD integration, and batch processing of threat groups.

Figure 1: CLI architecture showing data flow from user input through processing to output files

CLI Workflow

  1. Input: User provides threat group name via command line
  2. MITRE Lookup: System queries enterprise-attack.json for techniques
  3. Template Learning: Parses community repos, extracts patterns, caches templates
  4. Generation: Applies templates to techniques, generates vendor queries
  5. Correlation: Finds related techniques, creates multi-stage detections
  6. Visualization: Generates attack flow diagrams
  7. Output: Writes YAML files, JSON correlations, flow diagrams

Web/GUI Architecture

The web interface adds real-time progress tracking, file uploads, blog analysis, and interactive visualizations. Built with FastAPI for high-performance async operations.

Figure 2: Web architecture showing frontend-backend separation and async processing

Web Workflow

  1. User Interface: Browser renders HTML with JavaScript for interactivity
  2. API Routes: FastAPI handles /generate, /upload, /analyze_blog endpoints
  3. Background Processing: Async tasks run without blocking the UI
  4. Real-Time Updates: Progress JSON polled every 500ms for live status
  5. File Storage: Outputs stored in data/ directory structure
  6. Results Delivery: Download links served via /progress endpoint

🤖 AI Component - How It Works

Archer includes optional AI enhancement powered by OpenAI's GPT models. When enabled (by setting OPENAI_API_KEY), it provides semantic understanding and intelligent analysis.

What AI Enhances

1. Enhanced IOC Extraction

Without AI: Regex-based pattern matching (fast but rigid)
With AI: Contextual understanding of indicators 

Example:
Input: "The adversary used rundll32.exe dump) or (.exe .dll dump)))"
Regex: Extracts literal string with syntax errors
AI: Understands this is "rundll32.exe dump" with malformed syntax

2. Semantic Query Grouping

Without AI: Keyword-based categorization
With AI: Behavioral understanding 

Example Grouping:
Authentication Group:
- "Login attempts from ServiceAccount"
- "Kerberos ticket requests"
- "NTLM authentication failures"

AI understands these are related behaviors, not just keyword matches

3. Correlation Analysis

Without AI: Technique ID proximity
With AI: Multi-stage attack pattern recognition 

Example:
T1078 (Valid Accounts) + T1021 (Remote Services) + T1003 (Credential Dumping)

AI recognizes this as:
"Lateral movement attack chain:
 Compromise credentials → Access remote systems → Dump more credentials"

Models Used

Task Model Why
Complex Analysis gpt-4-turbo-preview Better reasoning, correlation understanding, fewer errors
Quick Extractions gpt-3.5-turbo Fast IOC extraction, cost-effective, good for simple tasks
Fallback Regex Engine Always works without API, no cost, privacy-preserving
✅ Privacy Note: OpenAI API does not retain data sent via API. You can disable AI enhancement entirely and Archer will fall back to high-quality regex-based extraction.

⚙️ Complete Workflow

Step-by-Step Process

Stage 1: Input & Lookup

User → Threat Group Name (e.g., "APT29")
     ↓
MITRE ATT&CK Lookup → enterprise-attack.json
     ↓
Extract Techniques → [T1059.001, T1078, T1003.001, ...]

Stage 2: Query Learning

Community Repositories
     ↓
Parse Queries (Splunk SPL, KQL, Sigma)
     ↓
Extract Patterns & Variables
     ↓
Create Jinja2 Templates
     ↓
Cache in data/cache/ for future use

Example Template: 

Template: powershell_execution
Variables: {process_name}, {command_line}
SPL: index=wineventlog EventCode=4688
     Image=*{{ process_name }}*
     CommandLine=*{{ command_line }}*

Stage 3: Detection Generation

For each technique:
    1. Load relevant templates
    2. Apply technique-specific values
    3. Generate Splunk query (SPL)
    4. Generate MDE query (KQL)
    5. Validate syntax
    6. Write to YAML file

Output: data/APT29/splunk/T1059_001_PowerShell.yml

Stage 4: Semantic Grouping (Optional)

All queries → Semantic analyzer
    ↓
Group by behavior:
    - Authentication behaviors
    - Network connections
    - File system operations
    - Process execution
    - Registry modifications

Output: Organized YAML files in subdirectories

Stage 5: Correlation Analysis

Find related techniques:
    T1078 (Valid Accounts)
         ↓ often followed by
    T1021 (Remote Services)
         ↓ enables
    T1003 (Credential Dumping)

Create multi-stage detection:
    - Stage 1: Detect valid account abuse
    - Stage 2: Monitor remote service usage
    - Stage 3: Alert on credential access

Output: data/APT29/correlations/vendor_correlations.json

Stage 6: Attack Flow Visualization

Generate Attack Flow diagrams:
    1. Correlation flows (per correlation)
    2. Complete actor flow (all techniques)

Format: ATT&CK Flow JSON schema
Output: data/attack_flows/APT29_complete_flow.json
        data/attack_flows/APT29_complete_flow.html

Stage 7: Output & Delivery

Final structure:
data/APT29/
├── splunk/
│   ├── T1059_001_PowerShell.yml
│   ├── T1078_Valid_Accounts.yml
│   └── ...
├── mde/
│   ├── T1059_001_PowerShell.yml
│   ├── T1078_Valid_Accounts.yml
│   └── ...
├── correlations/
│   ├── vendor_correlations.json
│   └── cross_vendor_correlations.json
└── attack_flows/
    ├── APT29_complete_flow.json
    ├── APT29_complete_flow.html
    └── correlation_flows/

📊 Attack Flow Visualization

Archer generates attack flow diagrams following the MITRE ATT&CK Flow specification. These visualizations show technique sequences and attack paths.

Types of Attack Flows

Correlation Flows

Generated for each multi-stage correlation

  • Shows technique sequence
  • Highlights relationships
  • Per-correlation diagram

Complete Actor Flow

Shows all techniques for a threat group

  • All possible attack routes
  • Tactical progressions
  • Comprehensive coverage

Attack Flow Schema

JSON Structure

{
  "type": "bundle",
  "spec_version": "2.1",
  "objects": [
    {
      "type": "attack-flow",
      "name": "APT29 - Complete Attack Flow",
      "description": "All techniques and possible routes",
      "scope": "campaign"
    },
    {
      "type": "attack-action",
      "technique_id": "T1059.001",
      "name": "PowerShell",
      "description": "Execution of PowerShell"
    },
    ...
  ]
}
💡 Interactive Visualization: Flow JSON files are automatically converted to interactive HTML visualizations that can be viewed in any browser.
