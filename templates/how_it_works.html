How Archer works: its architecture, the libraries it builds on and where it uses AI

Archer is an automated threat detection generator that transforms MITRE ATT&CK threat intelligence into production-ready detection queries for Splunk and Microsoft Defender XDR. It combines machine learning from community queries, MITRE ATT&CK intelligence, and optional AI enhancement to automatically generate comprehensive, correlated detection coverage in minutes. Its architecture prioritizes speed through caching, parallel processing, and async operations, while maintaining high accuracy through intelligent validation and correlation.

CLI/Command-Line Architecture

The CLI version provides direct programmatic access to Archer's detection generation engine. It's designed for automation, CI/CD integration, and batch processing of threat groups.

Figure 1: CLI architecture showing data flow from user input through processing to output files

Available CLI Commands

# Generate detections for a threat group
archer-cli offline generate "APT29"

# Generate detections for one technique (name or ID)
archer-cli offline hunt T1003.001

# Build correlation rules
archer-cli offline correlate "APT29"

# Adversary emulation (coming soon)
archer-cli offline emulate "APT29"

CLI Workflow

  1. Input: User provides threat group name or technique ID
  2. MITRE Lookup: Fetches techniques from STIX 2.0 bundle
  3. LOL datasets: LOLBAS, LOLRMM and LOLDrivers, for tools the group is seen using (ticked by default)
  4. OSINT Enhancement: Searches local repos (Google SecOps, Azure Sentinel, Splunk, Elastic)
  5. Generation: Extracts indicators, validates schemas, generates platform queries
  6. Correlation: Analyzes attack paths, scores relationships (0-140 points)
  7. Validation: Calculates detection likelihood (0-100), syntax checking
  8. Visualization: Generates MITRE ATT&CK Flow diagrams
  9. Output: Writes YAML detections, JSON correlations, flow diagrams to data/

Agents

An agent is a model in a loop with tools: it picks a tool, reads the result, and picks again until it can answer. The model never runs anything itself; Archer runs the tool it asks for and sends the result back. Tools that change something (hunts, saving a query) wait for your approval.

AgentPatternWhat it does
Detection repairCheck, fix, check again Static checks over a run's queries (Defender XDR schema, YARA-L and SPL structure); fixes what fails, re-checks, saves with a reason. A query that still has errors can't be saved.
Ask Archer (agent)Look it up Answers from coverage, results, ATT&CK and the library instead of memory; checks any query it writes; can start hunts.
Intel triagePlan across steps Report → techniques and IOCs → coverage gaps → hunt → briefing.

Run them from the Agents page, the console (use agent/repair) or any MCP client: archer-cli mcp exposes the same tools and the agents' prompts to Claude Code, Claude Desktop or your own agent. examples/agents/minimal_agent.py is a complete agent in about 100 lines. Full guide: docs/agents/README.md.

Frequently Asked Questions

What is Archer and what does it do?

Archer is an automated threat detection generator that transforms MITRE ATT&CK threat intelligence into production-ready detection queries for Splunk and Microsoft Defender XDR. It combines machine learning from community queries, MITRE ATT&CK intelligence, and optional AI enhancement to automatically generate comprehensive, correlated detection coverage in minutes.

Do I need an OpenAI API key to use Archer?

No, Archer works perfectly fine without an OpenAI API key. The AI enhancement is entirely optional and only improves certain features like IOC extraction accuracy and semantic understanding. Without AI, Archer uses high-quality regex-based extraction and pattern matching which is fast, free, and privacy-preserving.

Why is Archer so fast? Is it using AI or machine learning?

Archer is fast because it uses deterministic algorithms, not AI/ML inference. Here's exactly how speed is achieved:

1. Pre-Computed Intelligence (No AI Required)

  • MITRE ATT&CK Cache: Downloads and caches the entire STIX bundle once (enterprise-attack.json), then reads from local filesystem
  • Pattern Matching: Uses compiled regex patterns and dictionary lookups instead of neural networks
  • Template-Based Generation: Queries are generated from predefined templates, not generated token-by-token by LLMs
  • Rule-Based Logic: All correlation scoring uses mathematical formulas (0-140 point scale) instead of ML models

2. Parallel Processing Architecture

  • Background Threading: Detection generation runs in daemon threads, keeping UI responsive
  • Async I/O: FastAPI handles concurrent requests without blocking
  • Lock-Based Deduplication: Prevents duplicate correlation processing with thread-safe locks
  • Streaming Progress Updates: Real-time progress tracking via JSON file updates (no polling delays)

3. Smart Filtering (Not Machine Learning)

  • Attack Progression Filter: Simple dictionary lookup against 35 predefined tactic pairs
  • Semantic Overlap: Set intersection math (Jaccard similarity), not word embeddings
  • High-Impact Techniques: Hardcoded set of 30+ critical techniques, O(1) lookups
  • Correlation Grouping: Hash-based deduplication using technique IDs as keys

4. Efficient Data Structures

  • In-Memory Caching: Techniques, tactics, and procedures loaded once at startup (app.state)
  • Dictionary Lookups: O(1) average-case complexity for technique/group mapping
  • Set Operations: Fast indicator deduplication and overlap calculations
  • SQLite Database: Local file-based storage, no network round-trips

5. Optional AI Enhancement (When Enabled)

When you enable "AI-Powered Correlations", Archer CAN use OpenAI GPT models, but this is:

  • Completely Optional: Disabled by default, requires explicit checkbox + API key
  • Limited Scope: Only used for advanced semantic analysis and IOC enrichment
  • Async Execution: AI calls don't block main generation pipeline
  • Fallback Logic: If AI fails or isn't configured, uses deterministic methods

Performance Benchmarks (Typical Hardware)

  • 100 detections generated: 15-30 seconds (no AI)
  • 500 correlation pairs evaluated: 2-5 seconds
  • OSINT comparison (Elastic/Splunk): 5-10 seconds per technique
  • Full threat group (30-50 techniques): 2-5 minutes total

What's the difference between OSINT Enhancement and OSINT Comparison?

OSINT Enhancement: Automatically incorporates battle-tested detection patterns from OSINT sources (Elastic, Splunk community rules) directly into your queries. This is enabled by default on the Hunt and Analyse tabs. What LOLBAS, LOLRMM and LOLDrivers document about binaries, RMM tools and drivers the group is seen using is a separate option, LOL datasets, also ticked by default.

OSINT Comparison: Compares techniques against OSINT databases and adds metadata to YAML files (visible in the "Show Details" button). This is reference-only and doesn't modify the queries themselves. Either option adds the known false positives that Elastic and Splunk rules document for the technique (LoFP-style).

How do correlations work?

Correlations: Combines queries for the same SIEM (Google SecOps, Defender XDR, Splunk or Elastic) into multi-stage detections. This is enabled by default and helps create detection chains that track attack progressions within a single SIEM platform.

The results page shows each technique in a correlation as an individual query block, stacked with "chained with" connectors. The combined JOIN query is available via "Show Combined Query" below the stack.

How does Semantic Analysis work?

Semantic Analysis groups queries by behavioral categories (authentication, network, file activity, process execution, etc.) rather than just by technique ID. This is enabled by default and helps organize detections logically, making them easier to review, deploy, and maintain. It includes advanced query parsing for intelligent syntax-aware merging.

What file formats can Analyse read?

The Analyse tab reads multiple threat intelligence file formats including: PDF, TXT, Markdown (MD), JSON, CSV, Excel (XLSX/XLS), Word (DOCX/DOC), and YARA rules (.yar/.yara). Archer automatically extracts TTPs (Tactics, Techniques, and Procedures) and IOCs (Indicators of Compromise) from these files.

What is the Profile tab used for?

The Profile tab lets you analyze an organization's threat landscape based on their domain. It automatically identifies industry-specific threats, geographic threat actors, technology stack vulnerabilities, and optionally supply chain dependencies. It then recommends relevant threat groups and can auto-generate detection queries for them.

What is Threat Briefing and how is it different from the AI Ask feature?

Threat Briefing generates a grounded, prioritised detection plan for a threat group. It is different from the Ask feature in a critical way:

  • Ask: Sends only the group name to the LLM — the LLM draws on its training data, which may be incomplete or outdated
  • Threat Briefing: Sends the actual MITRE ATT&CK technique list (all three attribution paths: direct, via software, via campaign) plus your current detection coverage — the LLM prioritises based on real data

What it produces

  • Coverage stats: How many techniques are already covered by your detection library vs. gaps
  • Top-N priority list: Ranked techniques with priority reasoning and specific detection approach per technique
  • Attack chain: Kill chain tactic progression for the group
  • Executive summary: 2–3 sentence briefing for SOC leadership

How to use it

  1. Enter a threat group name in the Generate tab (e.g., "Scattered Spider")
  2. Click Threat Briefing (the button below Generate Detections)
  3. Select the number of top techniques to prioritise (5 or 10)
  4. The briefing panel loads with coverage statistics, the ranked technique cards, and the attack chain

Requires: An LLM configured (Anthropic, OpenAI, or local Ollama). The briefing uses POST /api/threat-briefing and passes the complete technique/coverage context to the model.

What are the individual query blocks on the results page?

After generating detections and correlations, the results page now shows individual detection queries per technique within each correlation, stacked visually with "chained with" connectors between them. This replaces the previous single combined-query view.

What you see

  • Technique name — the MITRE ATT&CK technique name
  • ATT&CK ID badge — e.g., T1078 in a blue pill
  • Tactic badge — e.g., Initial Access in a green pill
  • Query block — the individual Splunk SPL or KQL query for that technique
  • Copy button — copies the individual query to clipboard
  • "chained with" connector — visual divider between techniques in a correlation

Combined query

The JOIN query that combines all techniques is still available — click Show Combined Query below the stacked blocks to expand it. This is the query you deploy to your SIEM as a single multi-stage alert.

Why this matters

Previously you could only see the combined JOIN query. The individual blocks let you understand exactly which technique each sub-query detects, copy individual queries for testing, and understand the attack chain before deploying the combined rule.

Can I customize the generated detection queries?

Yes! All generated detections are saved as YAML files that you can review, modify, and customize before deploying to your SIEM. The queries are designed to be production-ready but should always be tested in your environment and tuned to reduce false positives based on your specific infrastructure.

How do I customize mapping files for my environment?

Archer uses three mapping files to control detection generation for different environments:

  • indicatorMapping.json: Maps indicator types (cmd, file, ip, domain, etc.) to data sources and fields
  • platformMapping.json: Defines which platforms (Windows, Linux, AWS, Azure) are supported by each data source
  • fieldMapping.json: Maps generic field names to vendor-specific field names (e.g., process_name → ProcessName for Defender XDR)

Common customization scenarios:

  • Using custom Splunk indexes: Update indicatorMapping.json to replace default indexes with your own (e.g., index=custom_windows_logs)
  • Multi-cloud environments: Add AWS/Azure/GCP data sources to appropriate indicator types
  • Custom EDR solutions: Add new vendor mappings for CrowdStrike, Carbon Black, SentinelOne, etc.
  • Disabling unused sources: Remove or comment out data sources you don't have

Best practices: Always backup mapping files before modifying, validate JSON syntax, test with small groups first, and document your changes. See the Mapping Files Configuration Guide for detailed instructions and examples.

What data sources does Archer pull from?

Archer pulls from multiple authoritative sources:

  • MITRE ATT&CK: Official enterprise-attack.json for technique mappings
  • Community repositories: Elastic detection rules, Splunk security content
  • OSINT sources: 5+ open-source security repositories with 7,500+ detection rules
  • Threat reports: Uploaded files or analyzed blog posts/reports
Is Archer suitable for production use?

Archer generates production-quality detection queries, but as with any automated tool, you should review and test all detections in your environment before deploying to production. Different organizations have different baselines, and tuning is essential to reduce false positives and ensure the detections work correctly with your specific data sources and infrastructure.

How do I get started with Archer?

  2. Optionally enable AI-Powered Correlations if you have an OpenAI API key
  3. Click "Generate Detections" and wait for processing to complete

Does Archer work offline?

Archer requires internet access for the initial setup to download MITRE ATT&CK data and OSINT repositories. Once cached, it can generate detections offline without requiring external API calls (unless you enable AI enhancement). All OSINT sources are cloned locally, so Archer doesn't rely on external APIs for core functionality.

How does Archer handle software (malware/tools) in threat groups?

Archer uses software-to-technique traversal to extract actionable indicators from malware and tools. Instead of just detecting software names like "BlackCat" or "Mimikatz", Archer automatically:

  1. Identifies which techniques the software employs (e.g., BlackCat uses T1083 File Discovery, T1486 Data Encryption)
  2. Extracts technical indicators from those techniques (e.g., net use, fsutil behavior set)
  3. Merges these with the group's direct technique indicators
  4. Removes duplicates to create comprehensive detections

Example: For Scattered Spider using BlackCat ransomware, detections include specific commands BlackCat runs (like fsutil, vssadmin) rather than just looking for the "BlackCat" string.

This implements two indicator extraction paths:

  • Direct: Group → Techniques → Indicators
  • Software: Group → Software → Techniques → Indicators
How are correlations scored and prioritized?

Archer scores correlations on a 140-point scale based on six key factors:

  • Technique Criticality (30 points): High-impact techniques like credential dumping, lateral movement, and data exfiltration score higher
  • Tactic Priority (20 points): Correlations involving critical tactics (Credential Access, Lateral Movement, Exfiltration, Impact) score significantly higher than lower-priority tactics (Execution, Discovery)
  • Query Specificity (20 points): More specific queries with detailed indicators score better than generic ones
  • False Positive Rate (25 points): Lower estimated false positive rates increase the score
  • Attack Progression (25 points): Correlations that follow logical attack chains (e.g., Credential Access → Lateral Movement) score highest
  • Data Source Diversity (-10 to +20 points): Correlations spanning multiple data sources (e.g., process + network) get bonus points

Tactic Priority Weights:

  • Critical (10 pts): Credential Access, Lateral Movement, Exfiltration, Impact
  • High (8 pts): Privilege Escalation, Persistence, Command & Control
  • Medium (6 pts): Defense Evasion, Collection, Initial Access
  • Lower (3-4 pts): Execution, Discovery, Reconnaissance

Note: Semantic overlap (query field similarity) is calculated and displayed as informational metadata but does NOT affect scoring. What matters is whether the techniques form a meaningful attack chain, not whether they use similar log fields.

Minimum Threshold: Only correlations with 75% or higher relevance (score ≥ 105/140) are included by default. This threshold can be adjusted by setting CORRELATION_MIN_RELEVANCE in your .env file (range: 0.0 to 1.0).

How does Archer handle multi-cloud environments (AWS/Azure/GCP)?

Archer includes sophisticated cloud platform separation to prevent mixing AWS, Azure, and GCP indicators incorrectly:

  • Cloud-native logs: AWS CloudTrail, Azure Activity Log, and GCP Audit logs are only used for their respective cloud platforms
  • Endpoint detection: Endpoint logs (Windows, Linux, Defender XDR tables) can detect cloud CLI tools running on endpoints (e.g., aws, az, gcloud commands)
  • Automatic filtering: Detection queries automatically select appropriate log sources based on cloud platform context
  • No cross-contamination: AWS API calls won't generate Azure AD detections, and vice versa

This ensures clean, platform-specific detections while maintaining the ability to detect cloud CLI usage on endpoints.

How do correlation filters work?

Archer uses multiple intelligent filters to ensure only high-quality correlations are generated:

  • Attack Progression Filter: Only correlates techniques that follow logical kill chain sequences (e.g., Initial Access → Execution → Privilege Escalation)
  • Semantic Overlap Filters: Removes near-duplicates (>75% overlap) and completely unrelated pairs (<20% overlap)
  • Same-Table Deduplication: Prevents low-value correlations between detections querying identical data sources
  • High-Impact Requirement: Prioritizes correlations involving at least one high-value MITRE ATT&CK technique
  • Data Source Diversity: Awards bonus points to correlations spanning multiple data sources for better coverage
  • Correlation Grouping: Automatically deduplicates similar technique pairs, keeping only the highest-quality correlation

Result: 75-85% reduction in correlation noise while maintaining attack chain detection fidelity.

What is "Merge by Tactic" and when should I use it?

Merge by Tactic combines all detections under the same MITRE ATT&CK tactic (e.g., all Credential Access techniques), then correlates across tactics.

When to use:

  • Executive dashboards requiring simple, high-level view
  • Low-noise alerting for SOC environments
  • Phase-based threat hunting campaigns
  • Incident response workflows focused on attack progression

Benefits:

  • Generates 8-15 high-level correlations instead of hundreds
  • Represents entire attack phases (e.g., "All Credential Access → All Lateral Movement")
  • Broader detection coverage - catches ANY technique in the tactic
  • Reduces alert fatigue significantly

Trade-off: Less granular - you won't see which specific techniques triggered, but you'll know which attack phases occurred.

What is "Merge by Parent Technique"?

Merge by Parent Technique groups subtechniques under their parent (e.g., T1003.001, T1003.002, T1003.003 → T1003), then correlates parent techniques.

When to use:

  • Mid-level granularity between tactic-level and subtechnique-level
  • Tracking specific attack patterns without excessive detail
  • Correlating technique families (all OS Credential Dumping methods)

Benefits:

  • Moderate correlation reduction (~50-70% fewer than default)
  • Maintains technique-level context
  • Groups related attack methods logically
  • Good balance between detail and simplicity

Example: Instead of 9 correlations for every LSASS dumping variant, you get 1 correlation for "OS Credential Dumping (T1003)".

How can I test which correlation settings work best for me?

Archer includes a test script to evaluate different filter combinations:

python test_correlation_filters.py "Scattered Spider"

The script will:

  • Run correlations with baseline, merge-by-tactic, and merge-by-parent modes
  • Compare total correlation counts
  • Calculate average relevance scores
  • Identify high-quality correlation counts
  • Measure execution time for each configuration
  • Provide recommendations based on your specific threat group

Results are saved to a JSON file for further analysis. Use this to determine which mode produces the most actionable results for your environment.

What are the various approaches to building correlations available in Archer and how do I invoke each one?

Archer uses one correlation engine that automatically runs after detection generation. However, you can influence the quality of correlations by choosing different detection generation modes:

The Correlation Engine (Always Enabled)

Archer's correlation engine uses a rule-based heuristic scoring system with 6 factors (0-140 points) to intelligently pair detections within each vendor. This engine:

  • Automatically runs after detection generation completes
  • Cannot be disabled (always generates correlations)
  • Works entirely offline without AI
  • Provides deterministic, consistent results
  • Includes semantic analysis by default: Calculates semantic overlap between queries (0-100%) to filter duplicates and ensure diversity

Scoring factors: Technique Criticality (0-30 pts), Tactic Priority (0-20 pts), Query Specificity (0-20 pts), False Positive Rate (0-25 pts), Attack Progression (0-25 pts), Data Source Diversity (-10 to +20 pts)

Built-in semantic analysis: Always calculates token-based semantic overlap (Jaccard similarity) to filter correlations with >80% overlap (too similar)

Tunable parameters (Profile → Config):

  • Threshold: 40% (minimum relevance score to include correlation)
  • Per-Vendor Limit: 60 (max correlations per vendor)
  • Tech Frequency: 20 (max appearances of a technique in simple correlations)

Detection Generation Modes (Affect Correlation Quality)

The quality and types of correlations depend on what detections you generate. Choose a generation mode:

1. Standard Generation (Default)
  • How to invoke: Don't check any boxes (default)
  • What it does: Generates detections using template-based approach
  • Correlation result: Standard correlations based on templates
2. Advanced Parsing (Semantic Analysis)
  • How to invoke: Check "Advanced Parsing" in Web UI
  • What it does: Groups detections by behavioral categories during generation (authentication, network, file, process)
  • Correlation result: More semantically-related correlations that understand behavioral context
  • When to use: Complex attack chains where behavioral relationships matter
3. AI Generators (Optional)
  • How to invoke: Check "AI Generators" checkbox in Web UI
  • What it does: Uses LLMs to enhance detection generation quality
  • Effect on correlations: AI-enhanced detections → better quality input for correlation engine
  • AI Providers: OpenAI GPT (cloud) or local LLMs via Ollama/LM Studio
  • Requirements: OPENAI_API_KEY for cloud AI, or local LLM server for offline AI
  • When to use: Experimental AI-enhanced detection quality
4. AI Correlations (Optional)
  • How to invoke: Check "AI Correlations" checkbox in Web UI (requires "AI Generators" also enabled)
  • What it does: Uses LLMs to improve correlation JOIN query combination strategies
  • What it does NOT do: Detection pairing and scoring remain rule-based (6-factor, 0-140 points). AI cannot change which detections get paired or their relevance scores
  • Effect on correlations: Smarter JOIN query logic for combining detection queries
  • Requirements: "AI Generators" enabled + OPENAI_API_KEY
  • When to use: Experimental AI-enhanced correlation query combination

  ├─ Standard (default)
  ├─ Advanced Parsing (semantic grouping)
  └─ AI Generators (AI-enhanced)

Advanced Correlation Options

These options modify how the correlation engine processes results:

  • Merge by Parent Technique: Groups correlations by parent technique (e.g., T1003.001, T1003.002 → T1003) - Check "Merge by Parent Technique" in UI
  • OSINT Enhancement: Incorporate battle-tested detection patterns from OSINT sources (Elastic, Splunk) - Check "OSINT Enhancement" in UI
  • OSINT Comparison: Compare generated correlations with open-source repos to show alignment with community detection rules - Check "OSINT Comparison" in UI

Key Takeaways

  • ONE correlation engine: Rule-based heuristic with built-in semantic analysis (always active)
  • Detection generation modes: Affect the INPUT to correlation (quality of detections)
  • AI Generators: Enhances detection quality, providing better input for correlation engine
  • AI Correlations: Improves JOIN query combination logic, but scoring/pairing remain rule-based
  • Semantic analysis: Token-based overlap calculation (0-100%) is default, "Advanced Parsing" adds deep behavioral categorization
  • All correlations: Scored identically (6 factors, 0-140 points) regardless of generation mode or AI options
