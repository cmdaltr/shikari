Archer · detection generation flow

Fig · Archer

From an ATT&CK group, a CVE or a threat report to deployable, vendor-native detections and correlation playbooks. MITRESaw walks STIX for procedures and indicators; the generator emits one query per technique per SIEM; the correlation engine stitches them into attack chains.

01 Invocation

archer-cli

Supervisor & one-shot runs — archer-cli hunt, run, start.

Web UI

Server-rendered Jinja2 — Hunt, Coverage, Catalogue, Library.

HTTP API

FastAPI — /api/hunt, /api/threat-briefing, /api/correlate.

02 Input selector

ATT&CK group

172+ groups — attributed TTPs with threat-actor granularity.

CVE

Vulnerability → mapped techniques & exploitation behaviour.

Threat report

Uploaded URL / document → extracted techniques & IOCs.

03 MITRESaw · STIX traversal

Direct

Techniques the group uses directly in ATT&CK.

via Software

Techniques inherited from the group's (or its campaigns') tooling.

via Campaign

Techniques attributed through named campaigns.

Evidence

Procedure examples + detectable indicators per technique.

04 Query generator · two-tier

LLM tier

Compact prompt + evidence → vendor query. Ollama (local) or Anthropic. Degenerate-output guard.

Template tier

No-LLM path — MITRESaw indicators dropped into bespoke query templates.

Availability gate

Flags techniques whose data source isn't ingested — kept at generation, excluded at deploy.

05 Vendor-native queries

Google SecOps

YARA-L · UDM

Primary target. Event-type availability keyed on UDM metadata.event_type.

Defender XDR

KQL

MDE schema — DeviceProcessEvents, DeviceFileEvents.

Splunk

SPL

Field mapping via bespoke custom schema (no fixed CIM guarantee).

Elastic

ES|QL · ECS

ECS-mapped fields; availability gated on data connectors.

06 Correlation engine

Single-vendor

Chains techniques within one SIEM into a staged query sequence.

Cross-vendor playbook

Joins stages across SIEMs on host/user entities — a vendor-agnostic attack chain.

Relevance + window

Scores chains and sets a time window; ATT&CK is treated as goals, not a fixed order.

07 Artefacts & export

Detection YAML

data/groups/ — name, technique, query, severity, connectors, indicators.

Correlation JSON

data/correlate/ — single + cross-vendor chains, rendered on Results.

Detections-as-code

Push to the configured git repo — version-controlled rule set.

Interchange

MISP event · MACATable (→ VECTR) · STIX bundle.

The template tier and correlation engine run with no LLM at all — AI is opt-in. Detections are flagged (not dropped) when their data source isn't ingested, so coverage stays honest without silently thinning the rule set.
