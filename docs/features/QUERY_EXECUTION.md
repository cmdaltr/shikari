# Query Execution

Running a generated query against the SIEM and reading the results back.

## Splunk

`shikari/query/splunk.py` (`SplunkClient`) runs SPL through Splunk's search jobs API on the management port (8089) and reads the results back a page at a time. There's no page or CLI command that runs it yet; Detection Validation's Splunk instances use it (`shikari/validation/docker_manager.py`).

```bash
export SPLUNK_HOST=splunk.example.com
export SPLUNK_TOKEN=...                 # Settings > Tokens; or SPLUNK_USERNAME and SPLUNK_PASSWORD
export SPLUNK_PORT=8089                 # the default
export SPLUNK_VERIFY=1                  # check the certificate; off by default for a lab's self-signed one
```

```python
from shikari.query.splunk import SplunkClient

r = SplunkClient().execute_query(spl, earliest_time="-24h", max_results=0)   # 0: every result
if r["status"] == "success":
    rows, stats = r["results"], r["stats"]   # stats: row_count, result_count, truncated, scan_count, run_duration
else:
    print(r["error"])                        # Splunk's own message
```

- **Authentication**: a token goes as `Authorization: Bearer`; a username and password get a session key, renewed once if it expires mid-run.
- **SPL**: a bare search gets the `search` command in front; one starting with `|` (`| tstats`, `| makeresults`) is sent as written. A time term in the SPL (`earliest=-1d`) wins over `earliest_time`.
- **Paging**: `page_size` results per request (1,000 by default) until `max_results` or the job's result count; `stats.truncated` says when `max_results` cut it short.
- **Errors are returned, not raised**: bad SPL (Splunk's parser message), an expired or revoked token, a failed job, a timeout (the job is cancelled), Splunk unreachable. 429 and 503 are retried three times, honouring `Retry-After`.

### Validated

Against Splunk Enterprise 10 (the Docker image, trial licence) on the homelab, 10 November 2026 ([#44](https://github.com/cmdaltr/shikari/issues/44)), from inside Shikari's container: token and password authentication; a detection generated by `compile_splunk_queries` for T1082 run over the Windows 11 lab recording (Sysmon 1 and 4688 in the index's field names), 488 rows back; 2,500 results paged 1,000 at a time with none repeated; bad SPL, a revoked token, a wrong password and an unreachable host each reported. Rate limiting is covered by unit tests (`tests/test_splunk_client.py`): the lab Splunk wasn't made to refuse searches.
